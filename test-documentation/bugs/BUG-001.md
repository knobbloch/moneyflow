# BUG-001: created_at is returned with a non-UTC timezone offset

**Status:** Open – Fix pending verification  
**Severity:** Medium  
**Priority:** P2  
**Module:** Accounts / Transfers  
**Environment:** Local, Go API, PostgreSQL, Docker  
**Found during:** API Testing – Run 2  
**Date:** 2026-11-19  
**Test case:** TC-ACC-023

## Summary

The API returns the `created_at` field with a local timezone offset (+05:00) instead of UTC (+00:00).

This causes inconsistent timestamp representation in API responses.

## Preconditions

- Banking API is running.
- PostgreSQL database is available.
- API is accessible at http://localhost:8080.

## Steps to Reproduce

1. Send a POST request to `/api/v1/accounts`.
2. Create an account with valid data.
3. Check the `created_at` field in the response.
4. Inspect the timezone offset.

## Request

POST `/api/v1/accounts`

```json
{
  "owner_name": "Ivan",
  "currency": "RUB"
}
```

## Expected Result

The `created_at` field should be returned in UTC.

Example:

```json
{
  "created_at": "2026-11-19T14:56:06.385832Z"
}
```

The timezone offset must be `+00:00` or represented by `Z`.

## Actual Result

The API returns a timestamp with a +05:00 timezone offset.

Example from test execution:

```text
2026-11-19 19:56:06.38685 +0500 +05
```

Timezone offset: 18000 seconds.

## Evidence

Automated test:

`TestTC_ACC_023_CreatedAtIsUTC`

Execution result:

```text
--- FAIL: TestTC_ACC_023_CreatedAtIsUTC

created_at is not UTC,
offset 18000 s
```

## Root Cause

The repository scan functions retrieve `created_at` from PostgreSQL without normalizing the timezone to UTC.

Affected locations:

- `banking-api/internal/accounts/repository.go`
- `banking-api/internal/transfers/repository.go`

## Proposed Fix

Normalize the timestamp after scanning the database row:

```go
a.CreatedAt = a.CreatedAt.UTC()
```

And in the transfers repository:

```go
t.CreatedAt = t.CreatedAt.UTC()
```
