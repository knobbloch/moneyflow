# BUG-002: API accepts invalid JSON with trailing data

**Status:** Open  
**Severity:** Medium  
**Priority:** P2  
**Module:** Accounts API  
**Environment:** Local, Go API, PostgreSQL, Docker  
**Found during:** API Testing – Run 2  
**Date:** 2026-11-19  
**Test case:** TC-ACC-022

## Summary

The API accepts a request containing a valid JSON object followed by additional invalid characters.

The server processes the request and creates an account instead of rejecting the malformed JSON.

## Preconditions

- Banking API is running.
- PostgreSQL database is available.
- API is accessible at http://localhost:8080.

## Steps to Reproduce

1. Send a POST request to `/api/v1/accounts`.
2. Include a valid JSON object followed by additional text.
3. Check the HTTP response status.
4. Check whether the account was created.

## Request

POST `/api/v1/accounts`

```json
{"owner_name":"Ivan","currency":"RUB"} garbage
```

## Expected Result

The API should reject the request.

Expected HTTP status:

`400 Bad Request`

Expected error code:

`INVALID_JSON`

No account should be created.

## Actual Result

The API accepts the request.

Actual HTTP status:

`201 Created`

Response example:

```json
{
  "id": "d732e0df-fee3-486a-87d1-eb4211b0ff75",
  "owner_name": "Ivan",
  "currency": "RUB",
  "balance": 0,
  "status": "ACTIVE",
  "created_at": "2026-11-19T19:56:06.385832+05:00"
}
```

An account is successfully created despite the invalid request body.

## Evidence

Automated test:

`TestTC_ACC_022_TrailingDataAfterJSON`

Execution result:

```text
--- FAIL: TestTC_ACC_022_TrailingDataAfterJSON

status: got 201, want 400

body: {"id":"d732e0df-fee3-486a-87d1-eb4211b0ff75", ...}
```

## Possible Root Cause

The JSON decoder may decode the first valid JSON object without checking whether additional data remains in the request body.

The request handler should verify that the request contains exactly one valid JSON value and no trailing data.

## Proposed Fix

Review the JSON decoding logic in the account handler.

Ensure that after decoding the request object, the decoder checks for EOF.

Additional non-whitespace data after the JSON object must result in `400 INVALID_JSON`.
